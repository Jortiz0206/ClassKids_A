
# RETROSPECTIVAS
## Proyecto ClassKids – Sistema de Seguimiento Académico

**Fecha de actualización:** 24/11/2026  
**Integrantes:** Johanna Ortiz, María Alejandra Guio y Jan Llanos  
**Estado documental:** Retrospectiva de cierre elaborada y formato de seguimiento disponible.

## 1. Introducción

La retrospectiva es un espacio de reflexión que permite identificar los aspectos positivos del trabajo realizado, reconocer las dificultades presentadas y establecer oportunidades de mejora para futuros ciclos de desarrollo.

En ClassKids se elaboró una retrospectiva de cierre a partir de los aprendizajes, las dificultades y los resultados identificados durante el desarrollo del proyecto.

No se encontraron registros históricos suficientes para documentar retrospectivas formales por cada sprint. Por esta razón, no se atribuyen reuniones, participantes, acuerdos o compromisos que no cuenten con evidencia.

## 2. Retrospectiva general de cierre

La revisión del proceso de desarrollo permitió identificar los siguientes aspectos:

### 2.1. ¿Qué salió bien?

- Se logró construir una plataforma con diferentes módulos para el seguimiento académico.
- Las historias de usuario facilitaron la organización de las funcionalidades.
- Se avanzó en la integración de los componentes del sistema.
- Las pruebas permitieron identificar comportamientos que necesitaban correcciones.
- Se fortaleció la documentación técnica y funcional.
- Los integrantes adquirieron experiencia en análisis, programación, integración y revisión de software.

### 2.2. ¿Qué dificultades se identificaron?

- La organización inicial del proyecto se realizó por fases y no contó con registros completos de Scrum.
- No se conservaron actas de todas las actividades de seguimiento.
- Algunas funcionalidades necesitaron ajustes después de su implementación.
- Fue necesario revisar la coherencia entre el código, los requisitos y la documentación.
- La distribución individual de algunas actividades no quedó registrada completamente.

### 2.3. ¿Qué podemos mejorar?

- Establecer objetivos claros para cada ciclo de trabajo.
- Registrar las tareas y responsabilidades de los integrantes.
- Mantener actualizado el Product Backlog.
- Documentar las decisiones importantes.
- Realizar revisiones periódicas del producto.
- Fortalecer la comunicación y el apoyo entre los integrantes.
- Conservar evidencias de las actividades y los resultados obtenidos.

## 3. Aprendizajes del equipo

El desarrollo de ClassKids permitió reconocer que la construcción de software requiere organización, comunicación y revisión constante.

También permitió comprender la importancia de documentar los cambios realizados, mantener actualizados los requisitos y comprobar que las funcionalidades correspondan con lo establecido en las historias de usuario.

Uno de los principales aprendizajes fue reconocer que no basta con desarrollar funcionalidades: también es necesario probarlas, documentarlas y verificar que el sistema funcione de manera coherente.

Como oportunidad de mejora, el equipo reconoce la importancia de llevar un seguimiento más organizado de las actividades y conservar registros de los acuerdos y avances durante futuros proyectos.
